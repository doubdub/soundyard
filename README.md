# 사운드야드 (SoundYard)

중고 음향기기·악기 거래 사이트 프런트엔드 프로토타입입니다. 빌드 도구 없이 정적 파일 세 개로 동작합니다.

## 실행

```bash
cd soundyard
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000`을 엽니다. `index.html`을 파일로 직접 열어도 되지만, 로컬 서버로 여는 편이 안전합니다.

## 구성

```
soundyard/
├── index.html          # 페이지 마크업
├── styles.css          # 전체 스타일 (데스크톱 4열 / 모바일 2열)
├── app.js              # 매물 데이터, 필터·정렬, 모달, 카카오 로그인, 마이페이지, 1:1 채팅, 등록, 문의 게시판
├── assets/             # 매물 썸네일 SVG 20종
└── tools/
    └── make_assets.py  # 썸네일 SVG 재생성 스크립트 (선택)
```

## 기능

- **카테고리** 16종 + 전체. 데스크톱에서는 두 줄로 펼쳐지고, 좁은 화면에서는 가로 스크롤입니다.
- **검색**: 장비명, 모델명, 브랜드, 지역, 카테고리, 설명을 실시간으로 검색합니다.
- **필터**: 거래 방식(직거래/택배)을 다중 선택하고, 최신순·낮은 가격순·높은 가격순으로 정렬합니다.
- **매물 상세**: 사진, 품명, 가격, 카테고리, 거래 지역/방식, 연락처(직접 등록한 매물), 상세정보, 판매자 정보, 조회·찜 수, 찜하기, 채팅하기.
- **마이페이지**: 헤더의 아바타·닉네임을 누르면 열립니다. 닉네임, 역할 배지(`관리자`/`카카오 회원`), 로그아웃 버튼과 **찜한 매물**·**내가 올린 글**·**채팅중인 매물** 세 탭이 있습니다. 각 탭은 개수를 배지로 보여 주고, 목록에서 바로 상세 모달 열기·찜 해제·삭제가 됩니다. 상세는 마이페이지 위에 겹쳐 열리고 닫으면 마이페이지로 돌아옵니다.
- **채팅 (1:1)**: 매물 상세의 `채팅하기`를 누르면 판매자와의 1:1 대화방이 열립니다(이미 있으면 그 방을 이어서 엽니다). 로그인하지 않았으면 로그인 모달을 띄우고, 로그인 후 원래 매물의 대화방으로 이어집니다. 대화 화면은 매물 썸네일·품명·가격, 상대방 이름, 메시지 내역, 입력창과 전송 버튼으로 구성되고 Enter로도 전송됩니다. 왼쪽 화살표(뒤로가기)로 채팅 목록으로 돌아오고, 매물 정보를 누르면 해당 매물 상세가 열립니다. 내가 올린 매물에서는 안내 문구를 보여 주고, 받은 대화가 있으면 그 대화를 엽니다.
- **마이페이지 > 채팅중인 매물**: 참여 중인 대화를 **매물별로 묶어** 최근 대화순으로 보여 줍니다. 매물 행에는 썸네일·품명·가격·상대방 닉네임·마지막 메시지 미리보기·시각이 나오고, 한 매물에 여러 상대와 대화한 경우(`내 매물` 배지) 그 아래 상대별 스레드 목록이 펼쳐져 있습니다. 대화가 하나뿐인 매물은 행을 누르면 바로 그 대화로 들어갑니다. 대화가 없으면 빈 상태 안내를 보여 줍니다.
- **로그인**: 카카오 로그인 하나만 제공합니다. `app.js`의 `KAKAO_CONFIG.jsKey`가 비어 있으면 데모 계정(`사운드러버`)으로 로그인하고, 키를 넣으면 실제 카카오 JS SDK 로그인으로 전환됩니다(아래 [카카오 로그인 연동](#카카오-로그인-연동) 참고). 로그인하지 않고 판매하기나 채팅 문의를 누르면 로그인 안내가 뜨고, 로그인 후 원래 동작으로 이어집니다. 로그인 모달 아래 `관리자 테스트 로그인`을 누르면 `관리자`(role `admin`) 계정으로 바로 들어갑니다.
- **관리자 테스트 계정**: 로그인하면 판매하기로 매물을 바로 등록할 수 있고, 매물 상세에 `매물 삭제` 버튼이 보입니다. 문의 게시판은 비밀번호 없이 자동으로 관리자 열람 모드가 되고, 로그아웃하면 다시 잠금 상태로 돌아갑니다.
- **판매하기**: 카테고리, 품명, 가격, 연락처, 상세정보(선택), 사진을 입력합니다.
- **사진 WebP 압축**: 사진을 고르면 브라우저 `<canvas>`에서 긴 변 1200px로 리사이즈한 뒤 `image/webp`(quality 0.8)로 변환해 미리보기와 저장에 사용합니다. 압축 전후 용량과 변환 형식을 폼 아래에 표시합니다. WebP를 지원하지 않는 브라우저는 JPEG(0.8)로 대체합니다.
- **문의 게시판**: 문의 작성(제목, 작성자/연락처, 내용)과 목록을 제공합니다. 일반 이용자에게는 제목·본문이 `비밀글입니다 (관리자만 열람 가능)`으로 잠겨 보이고, 관리자 확인(데모 비밀번호 `admin1234`)을 거치면 실제 내용이 열립니다.
- **뒤로가기 연동**: 모달을 열 때마다 브라우저 히스토리 엔트리를 하나씩 쌓습니다(`history.pushState`). 안드로이드·브라우저 뒤로가기를 누르면 페이지를 벗어나지 않고 최상단 모달만 한 단계씩 닫히며(채팅방 → 마이페이지 → 메인, 채팅방 → 매물 상세 → 메인 등), 화면의 X·←·Escape로 닫아도 쌓인 엔트리를 함께 정리해 유령 히스토리가 남지 않습니다. 카카오 리다이렉트 복귀(`?code=`)의 `replaceState`는 기존 히스토리 상태를 보존합니다.
- **모바일**: 760px 이하에서 2열 그리드, 헤더 검색창 전체 폭, 모달 바텀시트, 카테고리 가로 스크롤로 전환됩니다.

## 데이터와 저장

기본 매물 20건은 `app.js`의 `SEED` 배열에 들어 있습니다. 가짜 외부 이미지 링크는 쓰지 않고 `assets/`의 로컬 SVG를 사용합니다.

브라우저 저장소(localStorage)에 다음 값을 보관합니다.

| 키 | 내용 |
| --- | --- |
| `sy_user` | 로그인한 사용자 |
| `sy_wishlist` | 찜한 매물 ID 목록 |
| `sy_custom_listings` | 직접 등록한 매물 (사진은 압축된 WebP data URL, `ownerId`로 작성자 구분) |
| `sy_deleted_listings` | 관리자가 삭제한 기본 매물 ID 목록 |
| `sy_inquiries` | 문의 게시판 글 (제목, 작성자/연락처, 내용, 작성 시각) |
| `sy_chats` | 1:1 채팅방과 메시지 (`listingId`, 판매자/구매자 ID·닉네임, 매물 스냅샷, 메시지 배열) |

관리자 열람 상태는 `sessionStorage`의 `sy_admin_session`에만 두므로 탭을 닫으면 초기화됩니다. 카카오 로그인 리다이렉트를 거칠 때 원래 하려던 동작(판매하기/채팅하기)은 `sessionStorage`의 `sy_kakao_intent`에 잠깐 담아 두고 돌아온 뒤 되살립니다.

채팅방은 매물 1개 + 구매자 1명당 하나입니다. 그래서 판매자 쪽에는 한 매물에 구매자별로 여러 대화방이 생기고, 마이페이지는 그것을 매물 단위로 묶어 보여 줍니다(같은 매물의 대화가 여러 개면 상대별 스레드 목록이 펼쳐짐). 메시지는 보낸 사람의 ID·닉네임과 시각을 함께 저장하며, 새로고침해도 남습니다.

시크릿 창이나 저장소를 비우면 초기 상태(기본 매물 20건 + 샘플 문의)로 돌아갑니다.

기존 샘플 매물과의 호환: 새로 등록한 매물은 거래 방식·지역 필드가 비어 있고, 상세 태그와 연락처는 값이 있을 때만 표시됩니다.

## 카카오 로그인 연동

`app.js` 맨 위의 `KAKAO_CONFIG` 세 값만 채우면 데모 로그인 대신 실제 카카오 로그인이 동작합니다.

```js
const KAKAO_CONFIG = {
  jsKey: '',      // 카카오 디벨로퍼스 > 앱 키 > JavaScript 키 (SDK 초기화·인가·토큰 교환 client_id)
  restKey: '',    // REST API 키 — 현재 로그인 흐름에서는 쓰지 않습니다
  redirectUri: '' // 비우면 현재 페이지 주소 사용
};
```

현재 배포본 `app.js`에는 사운드야드 카카오 앱(앱 ID `1657991`)의 JavaScript 키·REST API 키가 입력되어 있어 실제 카카오 로그인으로 동작합니다. 키를 비우면 데모로 돌아갑니다.

`jsKey`가 비어 있으면 예전처럼 `사운드러버` 데모 계정으로 로그인하고, 콘솔에 `카카오 로그인: 데모 모드`와 로그인 모달에 "데모 모드" 안내가 남습니다. `jsKey`를 채우면 `Kakao.init()`으로 SDK를 초기화하고 `카카오로 시작하기`가 실제 인가 화면으로 이동합니다.

### 동작 방식 (백엔드 없이 정적 페이지)

Kakao JS SDK v2에는 v1의 `Kakao.Auth.login()`이 없고 토큰 발급도 하지 않습니다. v2는 `Kakao.Auth.authorize()`로 `redirectUri`에 **인가 코드(`code`)** 만 돌려주므로, 토큰은 따로 받아야 합니다.

1. `Kakao.Auth.authorize({ redirectUri })` → 카카오 로그인/동의 → `redirectUri`로 `?code=...&state=...` (취소·실패 시 `?error=KOE320&error_description=...`)
2. 돌아온 페이지에서 `POST https://kauth.kakao.com/oauth/token` 으로 인가 코드를 토큰으로 교환 (브라우저에서 직접 호출, `kauth.kakao.com`은 CORS를 허용합니다)
3. `Kakao.Auth.setAccessToken(access_token)` → `Kakao.API.request({ url: '/v2/user/me' })` 로 회원번호·닉네임 조회
4. 닉네임으로 `sy_user`에 저장하고 주소창의 `code`/`state`를 지웁니다. 로그아웃 시 `Kakao.Auth.logout()`으로 토큰도 폐기합니다.

토큰 교환의 `client_id`는 JavaScript 키(`KAKAO_CONFIG.jsKey`)입니다. `Kakao.Auth.authorize()`가 그 키로 인가 코드를 발급하므로 교환도 같은 키로 해야 하며, REST API 키를 넣으면 `401 invalid_client / Bad client credentials`(KOE010)로 거절됩니다. 교환 요청에는 `client_secret`을 보내지 않으므로 콘솔의 Client Secret은 **사용 안 함**이어야 합니다.

### 카카오 디벨로퍼스에서 해야 할 설정

| 항목 | 값/상태 |
| --- | --- |
| 앱 키 > JavaScript 키 | `KAKAO_CONFIG.jsKey` (SDK·인가·토큰 교환 모두 사용) |
| 앱 키 > REST API 키 | 사용하지 않음 (`KAKAO_CONFIG.restKey`에 보관만) |
| 플랫폼 > Web > 사이트 도메인 | `https://doubdub.github.io` (로컬 테스트 시 `http://localhost:8000`도 추가) |
| 카카오 로그인 > Redirect URI | `https://doubdub.github.io/soundyard/` — 등록 값과 요청 값이 **정확히** 같아야 함 (`index.html` 없이 디렉터리 주소) |
| 카카오 로그인 > 일반 | 카카오 로그인 **활성화 ON** |
| 카카오 로그인 > 보안 > Client Secret | **사용 안 함** — 켜져 있으면 브라우저의 토큰 요청이 `invalid_client`로 거절됨 |
| 동의항목 | 카카오계정(닉네임) 사용 — 없으면 닉네임 대신 `카카오 회원`으로 표시 |

`KAKAO_CONFIG.redirectUri`를 비워 두면 `location.origin + location.pathname`(`index.html`은 제거)을 씁니다. 위 표의 Redirect URI와 같아야 합니다.

### 주의

- REST API 키가 `app.js`에 들어가고, Client Secret을 끈 상태에서는 인가 코드를 가진 사람이 누구든 토큰을 받을 수 있습니다. **시안·임시 공개용**으로만 쓰고, 실제 서비스에서는 인가 코드 교환과 회원 저장을 Cloudflare Workers로 옮기세요(4번 단계만 서버 호출로 바꾸면 됩니다). 그때는 Client Secret을 켜고 `client_secret`을 서버에서만 다룹니다.
- 카카오가 Redirect URI를 엄격히 비교하므로 `http`/`https`, 끝 슬래시, 서브 경로를 그대로 맞춰야 합니다.
- 로그인 실패 시 브라우저 콘솔에 확인해야 할 설정 7가지가 순서대로 찍힙니다.

## 백엔드 연동 메모

- `SEED`를 API 응답으로 바꾸고 `allListings()`를 서버 조회로 교체하면 목록이 서버 데이터가 됩니다.
- 등록(`handleSell`)의 마지막 단계에서 localStorage 대신 API를 호출하면 됩니다.
- 채팅은 `openChatForListing()`(대화방 생성·조회), `sendChatMessage()`(전송), `chatGroups()`(매물별 묶음)가 저장 지점입니다. D1 연동 시 `chat_rooms(id, listing_id, seller_id, buyer_id, created_at, updated_at)`와 `chat_messages(id, room_id, sender_id, body, created_at)` 두 테이블로 옮기고, 방 목록은 `listing_id`로 묶어 최근 메시지순으로 내리면 됩니다. 실시간 수신은 Workers의 WebSocket 또는 짧은 폴링으로 붙입니다.
- 매물 ID는 현재 `sy-001…sy-020`, 직접 등록은 `u-<timestamp>`, 문의는 `q-<timestamp>` 형식입니다. 서버 연동 시 실제 ID로 교체하세요.
- 이미지 경로는 `image` 필드 하나로 관리됩니다. 업로드 이미지는 압축된 data URL이 들어가며, R2에 올린 뒤에는 이 필드에 URL을 넣으면 됩니다.

### 문의 게시판 관리자 인증 교체 지점

지금은 시안 확인용 클라이언트 인증입니다.

- 비밀번호 상수: `app.js`의 `ADMIN_PASSWORD` (`admin1234`)
- 인증 처리: `init()` 안의 `els.adminForm` submit 핸들러와 `setAdmin()`
- 열람 판정: `renderInquiries()`의 `state.admin`

실제 서비스에서는 이 세 지점을 서버 인증으로 바꿉니다. 문의 목록은 Workers API에서 관리자 세션(JWT/쿠키)을 검증한 뒤에만 본문을 내려주고, 비관리자 요청에는 제목·본문 대신 잠금 상태만 반환해야 합니다. 클라이언트에서 숨기는 방식은 저장된 데이터를 직접 볼 수 있으므로 인증으로 쓰지 않습니다.

| 계층 | 서비스 | 무료 티어에서 맡는 역할 |
| --- | --- | --- |
| 프런트엔드 | Cloudflare Pages | `index.html`/`styles.css`/`app.js`/`assets` 정적 배포, 전 세계 CDN 캐시. 빌드 없이 저장소 루트를 그대로 배포 |
| API | Cloudflare Workers | 매물·문의 CRUD, 카카오 로그인 콜백, 관리자 인증. 무료 플랜의 일일 요청 한도 안에서 운영 |
| DB | Cloudflare D1 (SQLite) | 매물, 문의, 채팅방·채팅 메시지, 사용자, 관리자 세션 메타데이터. 이미지 본문은 저장하지 않음 |
| 이미지 | Cloudflare R2 | 압축된 WebP 원본만 저장. 무료 티어에 월 저장량과 읽기 요청 무료 한도가 있고, R2 공개 버킷이나 Worker 프록시로 서빙 |
| 인증 | 카카오 OAuth | 카카오 로그인만 유지. Workers에서 인가 코드 교환 후 세션 발급 |

비용을 낮게 유지하는 원칙:

1. **업로드 전에 브라우저에서 압축**합니다. 긴 변 1200px·WebP 0.8이면 일반 사진이 100~300KB 수준이라 R2 저장량과 전송량이 함께 줄어듭니다.
2. **이미지는 R2, 텍스트는 D1**로 나눠 D1 행 크기와 쿼리 비용을 줄입니다.
3. 목록 응답에는 썸네일 URL만 넣고 원본은 상세에서만 불러옵니다.
4. Pages CDN 캐시로 정적 자산 요청이 Workers 한도를 소모하지 않게 합니다.

연동 순서 제안: ① D1 스키마(`listings`, `inquiries`, `users`, `chat_rooms`, `chat_messages`) 생성 → ② Workers에 읽기 API → ③ 문의 API와 관리자 인증 → ④ 카카오 OAuth → ⑤ `fetch` 호출로 `SEED`/localStorage 대체.

## 참고

- 로그인은 위 [카카오 로그인 연동](#카카오-로그인-연동) 설정을 채우기 전까지 데모 계정으로 동작합니다. 카카오 로그인을 마치면 회원 정보는 브라우저 `sy_user`에만 저장되고 서버 세션은 아직 없습니다.
- 채팅은 이 브라우저의 `sy_chats`에만 저장되는 시안용입니다. 상대방(판매자·구매자)은 자동으로 응답하지 않고, 다른 브라우저나 기기와 대화가 공유되지 않습니다. 실제 서비스에서는 서버 저장과 실시간 수신이 필요합니다.
- 사진을 첨부하지 않으면 선택한 카테고리의 기본 썸네일이 붙습니다.
- 문의 게시판의 관리자 비밀번호는 소스에 노출된 시안용 값입니다. 실제 배포 전 반드시 서버 인증으로 교체하세요.
